## Method

1. Mechanical scan of every worktree: branch/detached HEAD, HEAD SHA, `git cherry` non-equivalent (`+`) vs patch-equivalent (`-`) commit counts against the integration HEAD, dirty-file inventory.
2. Every worktree carrying at least one non-patch-equivalent commit (`+` count > 0) was adjudicated individually by an independent adjudicator (three-part adjudication, appendix A) using identifier evidence (symbols, test names, byte-identical content) — never commit messages alone.
3. Every worktree with uncommitted changes was triaged by diffing each dirty file against the integration HEAD.
4. Dispositions are exactly one of: `ALREADY_PRESENT`, `ACCEPTED_AS_IS`, `ACCEPTED_PARTIALLY`, `REIMPLEMENTED`, `SUPERSEDED`, `REJECTED`, `NO_UNIQUE_CHANGE`.
5. Nothing was merged blindly: `git cherry` patch-equivalence only ever *dismisses* a worktree (proves its content already exists), never *admits* one. Every admission went through per-worktree semantic review and is listed as a special case below.
