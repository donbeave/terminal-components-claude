## Pinned component behavior: obscure reachable keyboard capabilities

Inspected only Holla's exact dependency revision `tailrocks/termrock@d8c438a894143c28b25da0599d5100bfb399ae2c` (Cargo.toml:23), checkout `/Users/donbeave/.cargo/git/checkouts/termrock-80ba21de23b1804f/d8c438a`. No prototype branches/history inspected.

- **L30 — Query editing shortcuts:** Holla menu.rs:696–707 delegates all Char/Backspace/Delete keys to TextInput. Thus Ctrl-A selects whole query, Ctrl-Z undo, Ctrl-Shift-Z/Ctrl-Y redo, Ctrl-W or Ctrl-Backspace deletes previous word, selected-text replacement/backspace/delete work. Dependency `crates/termrock/src/widgets/text_input.rs:618–714`. Left/Right/Home/End do NOT reach input; host uses list/preview navigation. Ctrl-C/V produce clipboard requests that Holla ignores; Ctrl-X mutates selected text but host does not fulfill clipboard copy. Do not claim working system clipboard integration from widget support.
- **L16 refinement — Home/End and PageUp/PageDown:** reachable list navigation to first/last or pagewise, inherited from dependency `crates/termrock/src/interaction/intent.rs:171–198`; Holla menu.rs:727 delegates these. j/k, space-toggle, slash-list-filter and typeahead from dependency are intercepted as search text by Holla, so not extra launcher bindings.
- **L19 refinement — Preview scroll:** dependency `crates/termrock/src/scroll/mod.rs:263–327` maps Up/Down/PageUp/PageDown and horizontal Right; Holla intercepts Left to return to list, and all printable h/j/k/l as query editing. Thus dependency supports both horizontal directions but host only exposes rightward movement. This legacy limitation should not be recreated in Junie; readable long previews is underlying capability.
- **L21 refinement — Confirm choices:** arrows Left/Up previous; Right/Down next; h/k and l/j aliases; Home/End first/last; Enter confirms current choice; Esc cancels. Dependency `crates/termrock/src/interaction/intent.rs:452–469`, `widgets/dialog.rs:1544–1561,1610–1620`; menu.rs:675–684 routes confirmation before query editing, so printable aliases work here. ## Important synthesis cautions (outcomes versus accidental limitations)

1. **Do not label “Git” or “Docker” one covered row.** There are current-repo/sibling batch/mirror/hygiene distinctions; Docker full cleanup, container remove, builder cache, and Compose workflows differ in scope and danger. Preserve origin + optional gitlab capability, but new model can show selected remote scope rather than falsely promise all remotes.
2. **Do not promise argv-only old implementation globally.** Dynamic project actions use argv, but legacy Docker stop/remove and image cleanup plus aggregate Brew upgrade still invoke shell. New parity plan should explicitly replace shell assembly with structured argv/dependencies while preserving actions, flags, targets and user outcomes. Image errors should become visible instead of silently swallowed; record semantic repair/conflict, not “literal parity”.
3. **Safety metadata is inconsistent legacy behavior, not a sufficient new policy.** Cargo clean destructive; Gradle clean mutating; task named clean mutating; Docker full prune destructive. Reclassify based on actual impact in previews/plans while retaining capability. Docker command-based cleanup is permanent/tool-native; no Trash promise.
4. **Trash recursive workflows are distinct from external command cleanup.** IDEA and Gradle clean-all use validated cleanup and Trash; local gradle clean and cargo clean delegate irreversible tool semantics. New plan must keep this distinction visible.
5. **Discovery has several unsupported cases.** Current Git commands require local .git marker while hygiene uses rev-parse ancestors; Cargo/current tasks don't search ancestor manifests; Make doesn't support GNUmakefile/lowercase makefile, included/dynamic targets, paths; Gradle wrapper isn't supported; Node doesn't check executable; mise doesn't sort/cap/check exit. Improvements are acceptable new behavior, but must not claim those were legacy features.
6. **Brew services are name discovery, not observed status management.** Every discovered service always has start/stop/restart; cache persists five minutes and doesn't refresh after mutations. If new preview only displays a service resource, it still lacks command variants, execution and cache/staleness interaction unless these are represented.
7. **Upgrade all vs standalone ordering/error policy matters.** Aggregate Brew shell chain short-circuits; standalone sequence continues after failure. Preview hides --yes actual argv and custom OMZ path. New plan should show truthful args, dependency blocks and partial results; avoid preserving misleading previews or conflating inventory with execution result.
8. **Descriptions can overstate real behavior.** “all remotes” is origin+gitlab, “running containers” includes stopped, Docker preview network rm differs actual network prune, Make “documented” means parsable, recursive Gradle clean is cwd subtree. Source-driven scope should replace prose claims in matrix.

## Important limits and source/document conflicts (not additional implemented features)

- L01 — No global CLI `--dry-run`, `--permanent`, selectors, JSON run results, task history command, scheduling/cron, env override, cwd override, config editor, trust revoke/list command, custom config path, or task retry. Complete parser `src/main.rs:37`; schema `src/config.rs:65`; runner model `src/tui/app.rs:187`. Dry run exists in cleanup-specific flows, audited separately. New activity persistence/retry/plan scheduling are category B unless required as improved parity architecture.
- L02 — `run` finds all registry action IDs, including actions opening interactive browsers/selectors. Only common `run_tasks` checks HEADLESS; generic `run` does not make arbitrary modal closures truly headless (`src/main.rs:115`, `src/main.rs:132`, `src/tui/app.rs:322`). Do not overclaim a universally noninteractive scripting API. Headless output is line-rendered, merges tasks without labels and retains ANSI bytes (`src/tui/app.rs:355`, `src/tui/app.rs:663`). `doctor` reports registered groups and counts, not complete per-probe success/failure diagnostics (`src/main.rs:143`).
- L03 — Every parallel headless task creates a separate thread reading shared stdin (`src/tui/app.rs:625`), no explicit prompt/input arbitration; bridge reader may block past stop flag until input returns (`src/tui/app.rs:749`). Preserve answerable prompts with safer explicit input ownership, not the race. PTY dimensions fixed 24×80; navigation escape sequences not forwarded; not a full embedded terminal emulator (`src/tui/app.rs:425`, `src/tui/app.rs:485`).
- L04 — Interactive runner returns Ok after closing even if task failed/cancelled (`src/tui/app.rs:1211`, `src/tui/app.rs:1222`); headless runner aggregates failure. Task outputs live only in memory and final terminal summary; generic execution has no persistent operation log/history/retry. Cleanup logs/frecency are separate implemented stores, not executor history.
- L05 — Trust is file-*content* scoped, not path scoped: identical contents at another location match same hash (`src/config.rs:108`, `src/config.rs:215`). Closure captures parsed command and hash; before launch it reloads trust store but does not reread project file (`src/providers/user.rs:100`). Therefore changed-file review re-prompts upon rescan/new process (proved integration test), not continuous file monitoring. Trust success means whole file accepted even dialog shows only selected action argv; successor should bind reviewed config/argv/cwd identity explicitly and show review scope.
- L06 — Collision reservations use incomplete hardcoded built-in IDs (`src/providers/user.rs:145`) missing newer dynamic/provider IDs. Later registry duplicate handling must be audited by launcher owner. Correct architecture should reserve actual registry IDs, preserve collision diagnostics; don't enshrine accidental collisions as compatibility.
- L07 — No custom action environment field; inherited environment and program PATH resolution apply (`src/config.rs:65`, `src/tui/app.rs:552`). No restrictions on explicit shell/interpreter executable in argv. `argv-only` means no implicit shell interpolation, not command sandbox or protection from malicious declared programs.
- L08 — Cancellation targets descendants remaining in owned process group; a child deliberately escaping into a new session is not generally contained. Test named `detached_grandchild` detaches stdio, not process session (`src/tui/app.rs:1366`). Avoid stronger safety claim than test/implementation.
- L09 — Trust dialog defaults Cancel, task-stop dialog defaults Stop; successor may improve safety defaults, but record semantics rather than assuming all old confirmations safe-default (`src/tui/trust.rs:46`, `src/tui/app.rs:1201`).
- L10 — Linux support is implemented Unix PTY/process-group behavior with Linux subreaper seam. `docs/linux-port.md` lists native apt/dnf and native systemd-user providers, XDG insight expansion, mount policy as follow-ups, not implemented baseline. Dependencies/package release CI are infrastructure, not parity backlog by themselves.

## Synthesis recommendations

Group final executable items around (1) versioned CLI registry/run/doctor contract; (2) custom-config parsing/discovery/provenance/trust review; (3) typed shared execution and sequential/parallel policies; (4) output/interactive stdin/attention/focus; (5) cancellation/reaping/error/result lifecycle. Each must link its constituent atom IDs. Don't equate simulated log lines with E29–E35, a plan confirmation with E07/E21, or a display-only provider row with machine-readable E03/E04. A deterministic fixture can represent parity UX, but must exercise the semantic branching and state ownership described above.

## Internal/documented claims and conflicts: do not inflate coverage

These are evidence qualifications for above rows, not independent promised functionality. New plan should preserve useful outcomes and structurally remove safety defects; do not reproduce legacy bugs.

1. **No disk/cleanup CLI subcommands.** Preview text `$ holla disk overview`, `$ holla disk analyze ...`, `$ holla cleanup review ...` is descriptive only. Actual CLI enum has Browse/List/Run/Doctor, no Disk/Cleanup (`src/main.rs:37`; providers disk `:25`, `:34`, `:43`; insights `:29`, `:46`). Actions are reachable via launcher/action Run; do not promise nonexistent headless disk JSON, `--dry-run`, `--permanent` CLI flags.
2. **Tree drilldown, not old-screen re-navigation contract.** Actual arrows/Enter expand/collapse projected tree through TermRock state (`src/tui/analyzer.rs:1222`); no in-analyzer root-change command. `r` rescans original root; `T` global Spotlight is not scoped to it. `SortKey::Name` is an internal enum/test capability, not a selectable analyzer sort (`:1196`). Apparent sort still displays allocated bytes (`:643`).
3. **No mouse events on owned screens.** Overview/analyzer/insights/path prompt only consume Event::Key (`src/tui/analyzer.rs:381`, `:1153`, `:1321`; `src/tui/insights.rs:260`). New mouse parity is design-system expansion, not inherited capability.
4. **Cleanup quit flow is broken, not verified graceful wait.** Press q/Esc during Deleting selects OpenQuit, replacing modal and dropping the sole report receiver (`src/tui/cleanup_flow.rs:208`, `:236`); choosing Stay clears modal, choosing Leave sets flag and clears modal (`:212`, `:231`, `:306`). Poll can only receive completion from Deleting (`:129`). Thus strings "Leave when finished", "cannot be interrupted", "Finishing safely" (`:374`, `:482`, `:514`) do not prove finish-before-exit/report ownership. New architecture needs Activity-owned operation independent of modal plus non-cancellable mutation/wait semantics, with deterministic completion-during-quit tests.
5. **Dry-run end-to-end inconsistency.** Shared cleanup flow always invokes `gradle --stop` when any selected policy requests it, even dry-run, and ignores task failure (`src/tui/cleanup_flow.rs:256`). Report state stores mode but not dry-run (`:68`), labels report successful dry-run paths Removed/Freed (`:543`, `:582`). Core test `dry_run_touches_nothing...` proves only selected filesystem preservation (`src/cleanup/mod.rs:617`), not all workflow side effects or truthful result copy. New typed effect boundary must make dry-run incapable of stopping processes/deleting and retain would-remove outcome through Activity/report.
6. **Guard policy is UI-owned.** DeletePlan only paths/mode/dry_run (`src/cleanup/mod.rs:28`); Xcode/Simulator/Gradle policy carried by CleanupItem created in insight UI (`src/tui/insights.rs:530`). Analyzer creates default-policy items (`src/tui/analyzer.rs:698`) for same paths. Process guard absent outside insight workflow; age eligibility assessed at enumerate/selection time, not execution. Broad universal app-running/age guarantees are false. Plan should centralize path/category guard validation if retaining safety across entry points.
7. **Protected descendants do not protect ancestor selections.** Denylist tests selected path, not recursively protected content (`src/cleanup/mod.rs:42`, `:90`). For example `~/Library` itself does not match protected-user cases though its Keychains/Application Support descendants do. Shared confirmation parent-dedup can drop stricter child policies (`src/tui/cleanup_flow.rs:336`). A new hierarchy-aware guard must retain strictest descendant policy and reject ancestor deletion that includes protected data; do not claim old implementation already does this.
8. **Size is estimate, not physical freed truth.** Scanner dedups hardlinks, delete-size traversal does not (`src/cleanup/mod.rs:393` versus `src/du/hardlinks.rs:9`). APFS clones/reflinks/purgeable content not reconciled. Separate candidate scans dedup within each scan, not globally across selected candidates. Never equate estimated sum with measured reclaimed bytes.
9. **Cache has bounded mtime evidence, not recursive freshness guarantee.** Capture only root/depth-two mtimes (`src/du/cache.rs:46`, `:196`), so deeper edits not affecting tracked mtimes can evade invalidation; failed/partial scans can cache partial sizes because snapshot does not filter node errors. 11. **Gradle/IDE helper swallows logging health.** `commands/cleanup_paths.rs:54` only tests failed/skipped, not log_errors; executor still logs best-effort. Preserve user-visible health in redesigned Activity without claiming helper already reports it.
12. **Platform text defect.** Analyzer unreadable guidance/APFS caveat unconditional (`src/tui/analyzer.rs:1007`), including Linux; Linux scanner itself is implemented, Spotlight unavailable, mac-only insights hidden. Target platform-aware explanation, same useful partial-accounting outcome.
