## 5. Strategic notes

- The heavy "what differs" analysis already exists on holla (`docs/refactoring-plan/branch-diff-*.md`, 620-clause obligation matrix, task catalog in `refactoring-tasks/`). This file's job is narrower: name what is *worth taking* and its evidence.
- Nothing on main should be cherry-picked by hash alone — the 774-commit lineage is interleaved with WIP snapshots later repaired. Port by file set at main HEAD, using the commit hashes above as review anchors.
- Two correctness streams must travel together: candidate 1's code **and** the BF01–BF14 repair list; taking the library without the repairs imports source-proven defects (including one test that freezes a wrong split-collapse expectation and one that freezes a disabled-hover defect).
- Holla-side features that postdate the integration reference (`02f5294b` scroll truthfulness, `92d91629` fades, one-click editing, HP journeys) have no main-side representation; porting main's `ScrollRegion`/input/list code over them is the conflict zone needing holla-first re-verification.
