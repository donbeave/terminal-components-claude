# Interaction audit

Scope: the current `holla-fable` worktree, inspected September 10, 2026. No other branch or history informed these findings. The component/API inventory is maintained separately; every capability discussed below already exists.

## Reproduced defects

The initial reproductions linked a fresh `cargo build --lib` into a temporary standalone Rust executable. The executable used only public component APIs and `catch_unwind` to record panic outcomes. These observations describe the pre-fix worktree; regression tests in the named modules are the authoritative evidence for remediation.

| Priority / classification | Exact evidence and impact | Structural cause / proposed fix | Risk / verification |
| --- | --- | --- | --- |
| P1 confirmed defect | `TextBuffer::selection_lines`, `src/core/text.rs`: `multi("日"); select_all(); selection_lines()` panicked. | Computing the last selected line by slicing at `selection.end - 1` turns a byte offset into an invalid UTF-8 boundary. Derive line coverage without slicing at an arbitrary byte. Enforce grapheme boundaries throughout the buffer API. | Medium: shared selection and editing model. Test multibyte endings, combining marks, emoji, public byte offsets, and multiline indentation. |
| P1 confirmed defect | `CodeEditor::on_key`, `src/widgets/code.rs`: editing `Ctrl+Enter` panicked at the `EditAction::Commit` unreachable arm. | Shared `edit_key` can emit Commit for modified Enter, but the consumer assumes it cannot. Define and handle the complete shared action contract. | Low. Test plain, Shift, Control, and Alt Enter through the editor API. |
| P1 confirmed defect | `CodeEditor::refind` / `goto_match`: searching for `é` in `İé` panicked. | Lowercasing changes byte length; match offsets from the transformed string are reused against the original document. Preserve original offsets during case folding. | Medium. Test expanding lowercase mappings before and inside matches and inspect match navigation/highlighting. |
| P1 confirmed defect, fixed | `DataTable::on_click_header` / `sort_by` / `commit_edit`: source rows `[b, a]`, begin editing `b`, enter invalid `!`, click ascending header, correct to `fixed`, commit. Runtime result was `[b, fixed]`; expected `[fixed, a]`. | Failed validation kept the editor open while header sorting changed display indices. `EditState.row` now explicitly means stable source row, matching `DataGrid`; begin/commit/click/render all use that identity. Repository callers do not consume the old display-index meaning. | Medium data-integrity risk. Regressions cover failed validation with header sort, every direct sort order, correction, cancellation, and clicks into other cells. |
| P2 confirmed defect, fixed | `DataTable::on_click_cell` and `DataGrid::on_click` moved the navigation cursor after commit validation failed. Repeating the click could replace the still-invalid edit buffer. | Cell navigation now stops when the existing edit still fails validation. | Low. Regression tests retain the original cursor, invalid buffer, error, and unmodified source/pending data across clicks. |
| P2 confirmed defect, fixed | `DataGrid::on_click` emitted a header `SortRequested` event after failed validation, permitting the owner to reload rows and discard the invalid draft. | A failed edit now blocks the header sort request before changing sort state. | Low. Regression proves no emitted event, unchanged sorting, and retained invalid draft/error. |
| P2 confirmed defect, fixed | `DataTable::render` and `DataGrid::render` computed edit-window offsets in display cells but applied `.chars().skip(offset).take(width)`. CJK/emoji suffixes disappeared; wide glyphs could cross the cell boundary. Editing clicks ignored that horizontal offset. | Both renderers now use the shared public `ui::text::slice_cells` helper, which retains grapheme boundaries and display positions, with clipped-edge markers. Both click paths apply the same display offset as the cursor. | Medium visual risk in clipped editing states. Rendered regressions cover CJK, ZWJ emoji, combining marks, Home/End geometry, click placement, and unchanged neighboring cells/gaps in truecolor and monochrome. Helper tests cover offsets inside wide glyphs, one/zero-cell widths, and windows past the text; its public example is a passing doctest. |
| P2 confirmed defect | `CodeEditor::on_paste`: after `begin_edit(); open_find(); on_paste("needle")`, document `hello` became `needlehello`; the find needle stayed empty. | Paste bypasses the active nested editing state. Route paste to the find editor before document editing. | Low. Test find open with both editing and navigation document modes; verify document remains unchanged. |
| P2 confirmed defect, fixed | `TextInput::validate`, `src/widgets/input.rs`: validate an empty required field, start editing, paste `valid`; error remained `Some("Required")`. | Validation assigned only failure states. Recompute the entire validation result, retaining custom-validator precedence. | Low. `required_error_clears_after_keyboard_and_paste_corrections` passes. |
| P2 confirmed defect, fixed | `TextInput::on_click`: masked `日a`, click immediately after the first bullet; cursor byte was 0, expected 3. | Rendering uses one cell per masked grapheme; clicking previously used the raw text's cell widths. Share displayed grapheme geometry. | Low. Tests cover CJK, emoji ZWJ sequences, combining marks, and scrolled masks. |
| P2 confirmed defect, fixed | `TextInput::render`: width 1 with help text panicked; cursor at the end of horizontally clipped text could sit outside the text rectangle. | Width arithmetic ignored the allocated rectangle; scrolling reserved no insertion-cursor cell and mixed glyph positions with ellipsis positions. Clamp geometry, reserve the cursor cell, and keep glyph coordinates aligned. | Medium visual risk at clipped widths. Tests exhaust widths 0–11, heights 0–3, help/error states, and prove no writes outside the allocation; wide-grapheme and masked scroll tests prove cursor/click alignment. |

## Additional source-confirmed findings

These have concrete control-flow evidence but were not independently reproduced by this audit's standalone executable. Their current remediation status must be checked against component tests and the consolidated report.

| Priority / classification | Evidence and impact | Proposed fix / risk / verification |
| --- | --- | --- |
| P2 confirmed defect | `src/bin/showcase/app.rs`, `App::on_mouse`: MouseDown focuses a field; MouseUp dispatches Click. `pages/inputs.rs`, `forms.rs`, `textareas.rs`, and `editor.rs` then calculate `was_focused` from the already-updated focus. A first click enters editing despite the documented focus-then-edit contract. | Preserve the focus state before the press or let the component's completed-click owner decide focus. Medium routing risk. Test first click, second click, press-drag-release, focus restoration, and navigation controls. |
| P2 confirmed defect | `Dialog::on_click`, `src/widgets/dialog.rs`, handles `DialogBody::Input` only. `DialogBody::Facts { ack: Some(..) }` renders/registers an acknowledgement input but its clicks fall through to Consumed. | Route both input body variants through the existing `input_mut` accessor. Low risk. Render a Facts dialog and exercise its input hit target, editing, paste, validation, and confirm button. |
| P2 confirmed defect, fixed | `TextArea::render`, `src/widgets/textarea.rs`, previously drew each line from column zero and clamped the cursor to the right edge. Long-line typing and cursor navigation could modify invisible text. | Added horizontal viewport ownership with shared cursor/click geometry. Tests cover Home/End, CJK/emoji/combining text, paste, narrow/normal/wide resize, and visible insertion in truecolor and monochrome. The existing Textareas showcase now includes a long Unicode line. |
| P2 confirmed defect, TextArea fixed | `TextArea::render` and `CodeEditor::render` previously called `scroll.ensure_visible(cur.line)` every editing frame. A wheel/scrollbar scroll away from the cursor was immediately undone by rendering. | TextArea now follows only when cursor position, editing activity, or viewport size changes; explicit wheel and scrollbar movement persists and hides an offscreen cursor. Tests verify manual scrolling followed by typing or cursor navigation. CodeEditor remediation is owned by its separate audit. |
| P2 architecture/API weakness | Several navigation handlers (`DataTable::on_key`, `DataGrid::on_key`, `TextArea::on_key`) match character/arrow codes without consistently checking modifiers, whereas other controls use `key.plain()`. Modified application shortcuts may be consumed as navigation. | Establish a shared binding policy before changing application shortcuts. Medium compatibility risk. Inventory actual modified shortcuts and test propagation through the application owner. |

## Verified existing mechanisms and remaining coverage

`FocusRing` and `HitRegistry` already provide modal barriers; later registered hit regions win. Showcase saves and restores dialog focus explicitly. `RenderCtx::control` excludes disabled controls from the focus ring, while disabled components own mouse rejection. `Viewport` already owns selection, drag autoscroll, scrollback, tail following, keyboard scrolling, and copy events. `DataGrid` and `DataTable` already support in-place edits and paste; `CodeEditor` already has horizontal scrolling, selection, find, highlighting, and diagnostics. `DiffViewer` composes `Viewport`. No new component follows from this audit.

Remaining audit work should concentrate on existing owners: modifier propagation through real apps, popup escape and focus restoration, Unicode search highlighting, and rendered interaction states in monochrome. Table edit failures during sorting/clicking and the shared table/grid Unicode edit window are covered by the fixes above. Public mutable geometry/index fields remain an API risk until their invariant policy is defined; that is an architectural finding, not evidence that every arbitrary mutation is a supported user flow.

Verification after the cell-window fixes: all 130 library tests and the public slicing doctest pass. The existing showcase `textarea_scrolls_with_wheel_and_keys` test passes with its original 28-line fixture contract preserved. Full formatting, Clippy, complete application test suite, deterministic app scenarios, and visual captures are consolidated by the parent audit and must not be inferred from these library-focused results.
