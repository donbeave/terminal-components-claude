## Deterministic scenario contract

`jackin-scenarios.tsv` is the machine-readable scenario index. Each row owns every intermediate checkpoint, not just the ending frame. It must be expanded into concrete deterministic tui-snap programs during the trusted baseline task before any implementation migration starts.

Notation:

- `fresh(world,motion,frame)` resets fixture state from the oracle. Defaults: Reduced, frame 0, fixed Junie theme; no real filesystem/network/clipboard/Docker/daemon/PTY/provider/op calls.
- `K(...)` sends the listed keys in order; `T(n)` advances exactly n production ticks, drawing after each tick. `type(...)` sends Unicode characters. `paste(...)` sends one bracketed paste event.
- `focus(id)` means Tab events until the named oracle focus id is reached, bounded by the captured ring length; it must never set focus directly. The trusted program freezes the resulting key sequence and expected ring. `select(label)` means the shortest explicit Home/Down sequence in the trusted oracle fixture, recorded before migration. It must never dynamically search the candidate frame.
- `click(label)`, `move(label)`, `down(label)`, `up(label)`, `drag(a,b)`, `wheel(region,n)` resolve coordinates from the trusted oracle's painted frame/hit map once per size. Coordinates are then fixed for both binaries. Ambiguous labels require an explicit region/ordinal. No candidate-derived coordinates or click-by-text escape hatch.
- `replay(test-name)` uses exactly the existing oracle test's actions and fixture mutations, with a frame/state checkpoint at every action. Tests with bounded wait loops must record and freeze their deterministic tick counts from the oracle. The production-view lane may observe state to assert it; it may not insert candidate-specific branches.
- `variant(...)` expands into separate fresh scenarios; it is not permission to sample one variant. Sizes separated by commas expand fully. Color matrix rows expand truecolor/256/16/none and NO_COLOR without explicit color. Full-motion boundary captures use oracle symbolic constants resolved from `rain.rs` into exact numeric ticks in the trusted manifest.

Every checkpoint compares complete cells (symbol including wide-cell continuation, foreground/background, modifiers), cursor position/visibility, dimensions, active route, overlay depth/purpose, focus owner, selected domain identities, scroll positions, and relevant fixture effect/state delta. Architectural checks separately reject dimension/scenario-specific painted substitutes and legacy interaction duplication. Identity assertions map semantic domain identities across APIs; private field names need not match.

### Trusted expansion algorithm and lane separation

The TSV is a bounded specification language, not an implementation-time instruction to discover behavior. Its compiler runs only against the pinned oracle. The baseline gate fails until every row and variant produces a flat, numeric event manifest. The manifest contains initial fixture data, size/color/motion, key code plus modifier bits, mouse kind plus zero-based coordinates, resize dimensions, explicit tick counts, checkpoint names, expected cell/cursor digest and semantic state digest. The candidate runner accepts only this flat manifest. It never receives selector labels or an adaptive wait predicate.

Use the actual oracle APIs in `app_tests.rs:14–85`: construct `App::for_scenario(scenario,motion,frame,Theme::junie())`; draw through `Terminal<TestBackend>` and `App::render`; dispatch `App::handle(Input::Key(Key {code,mods}))`, `Input::Mouse(Mouse {kind,pos})`, `Input::Paste(text)`, `Input::Resize(w,h)`, and `Input::Tick`. Resize the TestBackend before Resize, as `H::resize` does. The audit adapter observes production state; it does not replace production rendering or dispatch. Existing `H::ticks(n)` draws once after n ticks. Preserve that exact schedule when replaying tests; additional inspection draws are allowed only after proving they do not change state. New scenarios define a draw after each event explicitly.

Resolve `focus(id)` using the exact `H::tab_to` algorithm: inspect the current oracle focus, send Tab if different, repeat at most 24 times, fail if still different. Record every sent key and focus checkpoint. Resolve `select(label)` by first resolving the named tree/list focus, sending Home, then sending Down at most the oracle row count plus one until the selected domain row matches. Resolve fixture names to the exact oracle row identity, not substring text. Expansion fails on a missing, repeated, or ambiguous identity; it cannot drop that variant. This uses semantic row identity observed in the oracle adapter, never direct selection mutation.

Resolve a pointer label inside its explicitly named region from the oracle frame and hit registry. Require one text occurrence with the intended owner. Select the first painted cell of the label inside that owner's hit rectangle; for separator/scrollbar controls use the rectangle midpoint with integer division. Record the resulting `(x,y)` and owner. A double-click is Down/Up/Down/Up with no intervening tick (therefore inside the oracle's 500ms window). An outside click uses the first row-major cell outside all top-modal hits and inside the terminal. Regionless or duplicate labels fail expansion with their possible identities; the trusted baseline author resolves the row using the cited source before sealing the manifest. Relative drags use the stated four/eight cells, clamped only where the oracle's actual rectangle requires it; both start/end coordinates are sealed. Wheel counts mean that many distinct events; positive is WheelDown, negative WheelUp. Add horizontal WheelLeft/WheelRight variants to JA-064/065 using the same coordinates; oracle maps them to the same ±3 delta.

For `replay(name)`, copy the source test's initial fixture mutations and event ordering verbatim. Instrument `H::key`, `H::ctrl`, `H::mouse`, `H::resize`, and `H::ticks` to emit an event trace while retaining their normal behavior. Record the executed branch and exact loop iteration count. Freeze that trace; do not port conditional test branches into candidate replay. Source-defined typed strings, provider steps and save focus IDs therefore need no rediscovery. For loops not copied from a test, the bound is 1,024 production ticks; the target is the explicitly named route, launch stage, loading completion, or prefix state. Failure to reach it is a baseline error. Expand all finite sets (worlds, tabs, colors, listed errors and dirty-exit policies) in source enum order. Before accepting any selector resolution, independently replay the flat trace against a fresh oracle and require identical frames and state. This also catches accidental render-side mutation.

Replay continuation has an explicit route/tab/focus precondition. JA-024's intact hundred-role test finishes in Roles at +Load role (app_tests.rs:1192–1197); capture it, then Esc/4/Enter reaches Environments before config scrolling. JA-060's intact chrome test closes Inspect and finishes in Capsule (app_tests_chrome.rs:153–157); capture it, then F10/Right/Right/End/Enter reopens Compact Inspect through the production menu before its additional inputs. Never truncate the source replay or pretend its original final state was a desired suffix setup. `checkpoint(name)` adds a complete frame/state capture without an input; prove the inspection draw is state-neutral, as for all replay instrumentation.

Exact private state claims belong to the **production-view lane**: route, modal stack, focus, selected domain identity, original/pending workspace/config, registry/defaults, scheduled jobs, daemon topology, clipboard, entry/exit arbiter, tick/frontier and scroll offsets. Expose only observations through the audit adapter. The **PTY lane** asserts terminal-observable evidence: full cells/cursor, emitted text, mouse/key/paste encoding effects, resize, process exit code, and alternate-screen/raw-mode restoration. It must not claim direct proof of in-memory registry or clipboard from screenshots. Pair the two lanes by scenario/checkpoint ID, with exact animated/transient equality owned by controlled-clock production-view captures. PTY executable tests use real reachable startup states and fixed encoded event traces; model-only fixtures remain explicitly production-view-only.

The 140ms flash is not assumed to be reachable at precisely 139ms through route ticks. JA-065 captures the last reachable production tick before expiry and the first at/after expiry, recording their actual milliseconds; a separate pure interaction-clock test may assert the 139/140 threshold without calling it a PTY state. Likewise phase constants and prefix deadlines resolve to concrete values from the pinned source, never wall-clock sleeps.

Use production-view controlled clock for exact animated frames, transient loading/pressed/takeover, and model-only cases. Use actual CLI in PTY for reachable interaction sequences, terminal key encoding, mouse protocol, bracketed paste, resize, startup/exit and terminal restoration. Do not assume PTY wall-clock delays establish exact animation ticks. The verification specialist's pinned tui-snap protocol owns the exact capture adapter; this inventory does not invent a separate runner.

Injected edge fixtures are permitted only by constructing oracle production state before the first event. They must use the same initial data in both versions and be pinned as trusted inputs. In particular BlockedSidecar is modeled-only (`sim/launch.rs:87`), not falsely claimed to be reachable from the CLI. Provider outcomes and op errors are simulated by existing `sim/provider.rs`, `sim/onepassword.rs` and `sim/world.rs` job queue. No test should access a real credential or export real data. Clipboard assertions inspect `World.clipboard`.

Main themes added after the oracle remain architecture/API test coverage; they must not redefine the oracle's Junie appearance. Initial color compatibility and all interaction checkpoints run at the oracle's supported color levels. Capture motion seed `0x4A41434B494E5E5E`, clock epoch `1788401640`, per-route tick intervals, fixtures and app SHA in provenance.

## Ownership handoff

The task graph must map every JA-* row to the trusted-baseline task, a Jackin flow owner, relevant component owner, and final integration gate. Splitting responsibilities must not leave app-local compatibility painters as a permitted endpoint. Component owners should consume Jackin fixtures for tree/detail, config forms, overlay stack, terminal viewport, split panes, secrets, FileDiff, progress/meter and menus. Shared config semantics belong in reusable components/composition; workspace/account/provider policy stays in Jackin domain modules. Keep asynchronous save ownership, manager stable identities, credential masking and deterministic world tests already present on main.
