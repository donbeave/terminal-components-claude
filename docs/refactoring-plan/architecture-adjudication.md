## ADJ-01: Held pointer eligibility is already publication-owned

**Evidence.** Main `docs/sources/main/COMPONENT_ARCHITECTURE.md:8539` still calls dynamic disabling unspecified, and `runtime.rs:1107` does not call `deliverable` inside `pointer_captured`. Those facts do not establish a current defect. Commit `715ee0777e20a09e0f373b07024076bdc742ef1d` added the missing structural enforcement. Main `runtime.rs:1725` reconciles both the held press and capture after successful publication. `capture.rs:18` and `:30` resolve the actual owner/part against the published ring, live top layer, region kind and geometry. Disabled, absent, decorative, empty or layer-blocked targets cancel the gesture. This is a publication invariant, not a convention in each component's handler.

The current `pointer_capture_eligibility` integration target contains twelve tests, including `disabled_capture_cannot_receive_drag_or_click`, `disabling_then_reenabling_does_not_resurrect_gesture_or_cancel_feedback`, `dropped_disabled_frame_does_not_cancel_until_successful_publication`, and the corresponding removed-part, layer and resize tests. On 2026-09-11, `CARGO_TARGET_DIR=/tmp/tc-adjudication-target rtk cargo test --locked -p junie-tui --test pointer_capture_eligibility` ran against the pinned main worktree and passed **12/12**. This is actual focused execution, not a historical test-name claim.

**Decision.** Retain the implemented lifecycle. A successfully published ineligible target cancels its capture and press bookkeeping; subsequent Drag/Up must not resurrect or activate the gesture, including after re-enabling. A dropped or aborted frame does not publish its disabling state. Independent timed activation feedback is not erased by gesture cancellation. A still-eligible moved part retains the captured origin and area. Do not introduce a synthetic activating Release or DragEnd as cancellation notification, and do not add a new public cancellation API for this already-covered behavior.

**Rejected alternative.** Adding another unconditional disabled check to every component or rewriting `pointer_captured` solely because §73's prose is stale would duplicate the existing authority and risk changing publication semantics. Cancellation before a successful publication would also contradict the tested presentation boundary.

**Remaining proof.** Preserve all twelve tests and add genuine overlapping regions: later registered disabled top versus enabled bottom on the same layer, and a disabled top-layer control over a lower layer. Record intents for both owners. Fresh Press/Release/Click/DoubleClick/DragStart/Drag/DragEnd/Secondary must never fall through. Cross the overlap with disable-during-capture, release outside, re-enable, part removal and a new independent press. Keep Move/hover observation, disabled scroll-owner wheel routing, ClickOnly and outside-layer dismissal behavior. Current `runtime.rs:3122` uses neighboring controls; it does not close this overlap proof.

**Task implication.** C-RUNTIME is preservation plus bounded proof extension, not a mandatory cancellation rewrite. Update stale §73 evidence gaps and historical current-status joins while retaining what the earlier revision actually said. Application oracle trajectories still need execution; the twelve tests are not whole-app parity.

## ADJ-06: Complete opt-in ASCII conversion has an exact mapping

**Evidence.** Architecture §§27/35 accept a whole-set conversion obligation; §71 (`:8488`) explicitly defers the full table and already chooses SelectClosed `v` and SelectOpen `^`. **Planning decision, not a blessed frame.** Complete the existing opt-in ASCII conversion using the following exact single-byte, one-cell mappings. Preserve existing accepted typed-set values and Select mappings. Preserve role identity and all discriminants even when glyphs collide. Do not change default Junie/Paper glyphs, application oracle modes, dimensions, state semantics, or color policy. No new expected application frame may be generated from this table and called the historical oracle.

Quiet rules use horizontal `-`, vertical `|`, and `+` for all corners, tees and cross. Active rules use horizontal `=`, vertical `|`, and `+` for all junctions. Scrollbar track/begin/end use `|`; thumb uses `#`. The ASCII spinner sequence is exactly `["|", "/", "-", "\\", "|", "/", "-", "\\", "|", "/"]`. It retains the default ten-frame cycle length and every timing token; consecutive frames, including wraparound, differ. As an explicit whole-set call, conversion replaces a previously authored sequence with this fixed sequence; a later `.motion(...)` or `.glyph(...)` remains an explicit override. Repeating conversion is idempotent.

`ascii_glyphs()` does not silently change BorderSet or caller content. `borders_set(border::ASCII)` continues to invoke glyph conversion, so it is the complete built-in ASCII chrome opt-in; switching borders back keeps the existing sticky glyph semantics. A later caller override can intentionally contain Unicode. Therefore “whole ASCII glyph table” is not “every application cell is ASCII”: user text, syntax data and explicit custom slots remain caller content.

**Ambiguities and rejected alternatives.** PrimaryKey has no historical ASCII counterpart. `K` is chosen over `*` to keep the header glyph distinguishable from the compact PrimaryMark; `*` would be reversible but collapse the new role's visible distinction. Ellipsis uses `~`, not three dots, because three dots change reserved width. The unchecked box is a visible reserved blank, not an empty string. Warning uses `?` rather than sharing Error's `!`. Several roles intentionally share a glyph because they occur in distinct semantic contexts; role identity, adjoining labels, geometry and state modifiers remain separate. No requirement promises every one of 42 roles a globally unique character. The spinner is a changing sequence, not a static `*`, and its cadence is not redesigned.

**Task implication.** C-THEME's exact matrix must enumerate all 42 roles independently of the production conversion loop, every typed set field, all spinner frames, width-one/single-byte/nonempty constraints, idempotence, override order and unchanged default tables. Include actual component rendering, pressed/checked/unchecked/readiness distinction, tiny geometry and colorless output. This planning table fixes the implementation choice; it does not authorize a golden freeze or self-blessing. The TUI design policy informed the separation of semantic mapping from historical visual evidence; no gallery, frame, production file or baseline was written here.
