## Completed main architecture to preserve

`apps/holla/Cargo.toml` establishes the app package, the shared `junie-tui` runtime dependency and `junie-tui-testing` development dependency. `lib.rs` separates argument parsing from terminal acquisition, prohibits unsafe code, provides typed exit outcomes and initializes the simulation feedback clock. Do not restore the old monolithic binary/runtime plumbing.

`app.rs` separates typed route reduction from `draw(&self)`, keeps shared Brand/MenuBar/StatusBar/HintBar controls, polls retained owners for lifecycle callbacks, retires scrubbed overlays until final callbacks, and keys activities by stable identities. `screens/home.rs` uses shared TextInput and NavList; activity output uses shared TextViewport; review screens use shared List, Props and Dialog. These are real architectural assets, not proof that their current product composition matches the oracle.

`dispatch.rs` and `sim/catalogue.rs` re-resolve semantic intent at invocation and confirmation, independent of remembered row labels. `sim/plans.rs` binds a non-cloneable reviewed plan to exact target facts and an opaque review identity, validates again immediately before mutation, rejects replaced reviews, preserves partial-failure accounting, and prevents replay. `sim/pg.rs` binds PID/query/user/host/operation rather than selecting another blocker on confirmation. `domain/accounting.rs`, disk/Docker/debian validation, checked revisions and bounded clock arithmetic protect the simulation boundary. Keep these properties while restoring oracle policies and transitions.

## Compatibility decisions and proof obligations

Catalog lookup, display and execution are separate source surfaces.
