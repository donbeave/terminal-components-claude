## Findings and repair checks

1. TASK-024 originally introduced `PickerAction::Submit` without allowing the compile adaptation at `apps/showcase/src/pages/pickers.rs`. The pinned main match at lines 1037–1066 enumerates every existing action and has no wildcard. Adding the variant therefore breaks workspace compilation outside TASK-024's original source scope. The architecture allowed this through a public-enum change whose consumer inventory was not joined to task ownership. The bounded repair is an exact-file, compile-only match adaptation with the new capability left disabled; TASK-042 and later application owners still own enabling and product behavior. The conformance consumers at lines 3279–3285 and 3377–3383 have wildcard arms and do not require extra scope.

2. TASK-022 `README.md:143` originally retained a universal `D-GESTURE-AUTHORITY` sentence while the new decision introduced four distinct policies. A candidate could use that sentence to replace the accepted modern default or apply DataGrid behavior to DataTable. The repair must make this older decision DataGrid-specific and explicitly preserve default and DataTable policies in all owned copies. The enabling condition was adding a local source-policy exception without reconciling an older normative universal statement.

3. TASK-022's original new decision and W-022-01/09 described a current readonly cell as activating, without distinguishing global editability from a readonly column. Oracle `src/widgets/grid.rs:1335` branches on global `self.editable`; when that is true, `begin_edit` at lines 551–552 refuses a `read_only` column or pending-deleted row with Consumed and no action. It does not fall back to activation. The required repair freezes all three cases separately: globally noneditable current cell activates; globally editable eligible cell follows inline/cycle/external editing; globally editable readonly-column or pending-deleted cell does nothing. The enabling condition was treating several distinct source guards as one natural-language state.

4. TASK-024 W-024-08 originally requested an explicit generic Partial proof without stating its expected result when query submission is enabled. Oracle has no Partial state. Pinned main `filter_list.rs:648` consumes item actions whenever status is not Ready. Consequently a generic-default no-action control is supported, but a new opt-in Partial Submit policy cannot be derived from oracle Loading/Error. The bounded recommendation is to retain no-action for Partial in both capability states unless a separate authority explicitly selects a different behavior. This removes candidate-selected expected behavior from the host witness.

Author repair and final byte-recheck status are recorded in the handoff section below; findings above describe the reviewed pre-repair conditions, not a claim they remain in current files.
