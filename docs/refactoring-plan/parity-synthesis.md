# Independent UI/UX parity synthesis

The four applications exist on main, but source evidence demonstrates missing flows and incompatible compositions. No application has established equality to the required oracle. The largest common failure is independent ownership of visible content and interactive state: a historical-looking frame can cover an unrelated, incomplete or inert component model. Completing the architectural refactor must remove that condition through production public components and one controlled state/geometry path.

## Authority, method and evidence boundary

Oracle **O** is `02f5294bfdbf38004cc49130d0aff1d01f31434c`; candidate **M** is `7b27732a8c3c131760ec3438f641cb3c11343a42`. This auditor independently repeated `git rev-parse holla-fable-2026-09-10^{commit} main` and inspected Git objects at both SHAs. A removed old binary directory does not prove a removed application: M uses `apps/showcase`, `apps/holla`, `apps/jackin-preview` and `apps/tablepro`.

Inputs reviewed: [showcase.md](showcase.md), [holla.md](holla.md), [jackin.md](jackin.md), [tablepro.md](tablepro.md), their four scenario registers, [components.md](components.md), [component-parity.tsv](component-parity.tsv), and [verification.md](verification.md). Independent source samples cover the actual field/update split, conditional historical painters, TablePro's content renderer, Holla's scenario enum, application breakpoints, Holla's state inventory, Jackin's large-role fixture, fade arithmetic and grid/field activation. Source citations below use repository paths at O or M, not current-checkout line identity.

The application auditors report oracle suites passing: Showcase 41, Holla 143, Jackin 63, TablePro 35. Those observations prove the existing assertions; they are not new parity captures. Main Holla's reported 173 passing tests likewise do not prove the oracle experience. This synthesis does not claim an additional test run or measured cell diff.

## Consolidated application matrix

[application-parity.tsv](application-parity.tsv) preserves **361 unique scenario IDs**: Showcase 76, Holla 135, Jackin 70, TablePro 80. Its twelve columns include every goal §6 application-matrix field, explicit root-component stream labels, an app-flow owner label and eventual task IDs. Labels are decomposition inputs, not task-format metadata. `owning_task_ids=PENDING` is intentional at this investigation stage and must become existing canonical task IDs before final plan acceptance.

`reference_state` joins the exact scenario row and its cited O source. That row supplies fixture, dimensions, actions and observable checkpoints; the application document supplies its bounded expansion rules. `visual_proof` and `interaction_proof` describe **required, uncaptured** evidence. No row marked migrated or unverified implies equality; a source-proven defect is distinct from an unmeasured difference. The V prefix denotes the whole canonical frame, cursor and dimensions contract in verification.md, not an artifact that already exists.

The matrix is an index of specified scenario families, not 361 captured cases and not a proof that every combination is covered. Expansion multiplies worlds, modes, controls, palettes, dimensions and checkpoints. Flat capture IDs and cryptographic artifact hashes are baseline-execution deliverables. Source enums and instance inventories must bound that expansion before accepting the reference bundle. A broad `all`, `SWEEP` or `variant` phrase is never itself a passed coverage result.

Main status is assigned at the narrowest source-supported surface group. For example, shared Grid gaps apply to TablePro even where an individual query/model test already passes. Conversely, missing main Holla parity-world names do not imply that its eleven migrated worlds or executable are absent. Exact per-checkpoint candidate effects remain unmeasured.

## Direct-view proof versus real executable reachability

The production-view lane may observe private state and initialize reviewed deterministic model edge fixtures. It must dispatch actual App/component handlers and draw actual production views. The PTY lane must start a real binary through its real parser and replay encoded terminal events. It proves decoded input, actual cells/cursor, routing-visible effects, process exit and terminal restoration. A screenshot cannot prove an in-memory registry, clipboard, filesystem mutation or review token. Pair those hidden assertions with the production-view checkpoint using the same stable scenario ID.

Oracle `--page` establishes Showcase page startup; SC-SHELL-ALL-PAGES establishes in-process navigation. Holla `--scenario` establishes 34 actual worlds and Jackin eight. TablePro's C/W/L/T/Q presets are CLI plus event sequences. Calling `goto`, `set_surface`, setting an enum, or constructing a view proves none of those executable routes.

Existing tests that mutate their initial world must record that mutation in a **production-view fixture**, then separately replay a reachable user journey in PTY. Examples needing explicit splits include forced save failures, provider errors, stale-target races and arbiter uncertainty. Holla ROUTE/HP entries are not automatically all-PTY merely because their source function is an app test. Conversely, JA-024 naturally starts HardCases and must retain real-world reachability. JA-043 BlockedSidecar definitively cannot be claimed as an oracle PTY path.

App labels, desired focus names and selector text are baseline-author conveniences only. Resolve them against O into flat key counts and coordinates, then replay unchanged on M. Never find the candidate's current label or focus ring to retarget a mismatch. Preserve Down and Up as separate events; exact cells after Down alone and release outside prevent false activation success. Copy/selection assertions must retain original source text, not visually reconstructed graphemes.

## Product/architecture adjudications

1. **Oracle UX, accepted main ownership.** Preserve stronger main stable identity, generation, one-shot approval, async-save and captured-target validation internally. Restore exact reachable oracle wording, initial focus, prompts and event ordering. If a reviewed target becomes invalid, use the oracle's existing cancellation/status/review-return path. Adding a new prompt solely to retain a conflicting main expectation is not parity.
2. **One state for draw and input.** Replace app-local historical component replicas with reusable public components, controlled values and shared geometry. Public custom renderers/slots remain allowed for genuinely application-specific compositions. A blanket ban on painting would contradict the accepted author API; an inert visual replica beside a hidden editable model fails it.
3. **Authoritative app-specific routing.** Holla typing-hot query, TablePro narrow zero-area focus stops, Jackin terminal-prefix capture and Showcase sidebar current/cursor separation differ intentionally. Shared runtime policy must express these cases without normalizing them into one global key/focus behavior.
4. **Read-only output stays distinct from editing.** TextViewport owns borrowed projection, retained source identity, selection and follow policies; CodeEditor owns editing/find/completion contracts; Grid owns generic keyed cell interaction. App SQL, providers, virtual files and cleanup policy stay outside the library.
5. **Visual semantics can require shared structural work.** Fades run after content and before scrollbar; text graphemes span style runs; diff effective mode adapts to width while requested mode survives. Fix these once in shared ownership. Per-app opacity passes or static narrow screenshots leave the enabling bug class intact.
6. **No automatic widening of the product.** No new themes in oracle app runs, invented disabled picker rows/reference grid cells, new backend/provider calls, or new safety flows. Such reusable component states may be tested separately where the accepted API supports them.
7. **Timing has multiple clocks.** Preserve domain tick counts, elapsed deadlines and animation phases separately. Showcase submit is `>1800ms`, busy completion `>=2200ms` when eligible page ticks run; shell flash is `>=140ms`; statuses have app-specific strict boundaries. Jackin phase transitions must use reachable production clock values. No wall-clock sleep stands in for an exact transient frame.

## Coverage judgments and closure gates

The combined source inventories identify important applications, routes, component families and interaction classes. Concrete omissions from main are known, and the required oracle scenario set is substantially broader than the old candidate baselines. This supports factual decomposition; it does **not** support declaring all-states parity or accepting any baseline yet.

Before the baseline task can close, its trusted compiler/reviewer must publish an applicability expansion with columns `parent_scenario_id`, `instance_path`, `state_or_action`, `applicability`, `oracle_source`, `lane`, `numeric_action_manifest`, `checkpoint_ids` and `reason_if_not_applicable`. This is evidence data, not a replacement task-format task schema. Enumerate actual source page/route/modal enums, constructors, branches and component instances; enumerate all emitted Holla snapshot kind/parameter pairs. The finite source inventory, not the candidate's registered hits, defines the required set. Unknown/unclassified/ambiguous instances fail the gate. New source-discovered obligations add stable expansion IDs before sealing; they cannot be silently dropped.

Require the following independent checks:

- Bidirectional equality of scenario IDs across all four registers and application-parity.tsv; unique rows; existing source references; every row assigned an app owner, shared owners and later canonical task IDs.
- Every state branch and input owner in the application inventories maps to an explicit applicable instance, or a cited N/A reason. Broad rows such as SC-FOCUS, HO-POINTER-ALL and JA-067 must expand to named finite cases with frozen counts; sampling one variant fails.
- Every applicable instance includes its actual geometry/cells, relevant focus/hover/press/selected/disabled/error/empty states, supported keyboard and pointer actions, and scroll/edit/overlay/resize/time obligations from the table above. Unsupported combinations are excluded explicitly, never invented.
- Direct and PTY evidence report their separate scope. Reachable app flows require a real CLI/input trace; model-only variants remain direct. Private semantic observations and terminal-visible assertions must not be conflated.
- Reference capture repeats identically, binds source/adapter/binary/tool/font/profile/fixture/manifest hashes and survives negative comparator/tamper probes. No candidate regeneration or blessing can satisfy a mismatch.
- Cross-app verification uses the same reusable production implementation; exercise neighboring states of each old conditional painter and changing visible domain values. Static headings, Surface enum labels and constructor-only props checks cannot prove active wiring.
- Preserve valid current-main ownership/safety/performance tests while replacing product assertions that contradict O. Architecture and exact oracle parity must both pass at the tested integration head.

Planning limitations are explicit: no complete new canonical reference bundle exists in this audit; flat action expansion, exact transient clock qualification and complete PTY replay remain baseline-execution work. No known application capture feature has been shown impossible after the verification specialist's tui-snap assessment. Capture gaps are required work, not approved tolerances or reasons to redesign the product.
