This is a source audit for planning, not a report that the refactor passes. The immutable oracle is `02f5294bfdbf38004cc49130d0aff1d01f31434c` (`holla-fable-2026-09-10^{}` verified locally). The candidate source is main `7b27732a8c3c131760ec3438f641cb3c11343a42`. References below use `O:path:line` and `M:path:line` for those exact trees. Paths without a line identify the complete module. ## Evidence rules

Source presence establishes implementation shape, not successful runtime parity. `unverified` in the matrix means no comparison against the new immutable oracle has established equivalence. `missing` means the named behavior has a source-level contradiction or absent contract, with details below. `implemented; verify` means the architecture exists and must survive final proof. Existing test names and files are source-discovered coverage, not an assertion that they were executed. Tests derived from an older reference remain non-regression inputs, not the new oracle.

`M:docs/audit/main-holla/components.md` and its JSON inventory use older main `c12cad8` and reference `794b095`. Their findings C1, C2 and C4 have subsequently changed: `EmptyState::draw_inherited` exists with `tests/empty_style_inheritance.rs`; `ratatui-crossterm` is optional in `crates/tui/Cargo.toml`; `GridCell`, a borrowed custom painter, exists with `tests/grid_cell_renderer.rs`. Do not create duplicate implementation work for those old findings. The positional author example remains present and needs disposition under the accepted keyed identity rule.

## Source-proven parity work

### CP-01: Scroll edge rendering is missing from main

Oracle commits `92d91629` and `02f5294b` add `O:src/ui/fade.rs`. Main source has no equivalent fade application in `crates/tui/src/components` or `crates/tui/src/ui`. The exact visual contract is:

- Intersect content rectangle with buffer. Exclude scrollbar column, headers, and footers.
- Heights 0–3 have no fade. Heights 4–11 fade one row at each edge hiding content. Heights 12 and above fade two rows.
- Top fades only when `offset > 0`; bottom only when the nonzero viewport ends before content ends. Reaching a boundary removes that edge's fade immediately.
- RGB foregrounds retain 55% contrast on outer rows and 80% on inner rows, rounded componentwise toward the majority background of the content rectangle (`O:src/ui/fade.rs:26`). Cells with another background and reversed cells stay untouched. Tied background counts must preserve oracle behavior; do not replace majority-background semantics with an assumed theme surface without proof.
- Non-RGB cells gain `DIM` on outer rows only; their color and inner rows remain unchanged. Hardware-cursor rows and explicitly protected navigation/current rows remain whole.
- Apply after content paint and before scrollbar paint. Symbols, hitboxes, selection, geometry and focus must not change.

Oracle widget callers are code, completion, grid, list, panel/ScrollPanel, picker, props, steps, table, textarea, tree, viewport. Application callers also cover Showcase shell/sidebar, Holla cleanup/disk/files/finder/modals/plan/review/snapshot, and Jackin accounts/capsule/config/editor/inspect/manager/modals/usage. Shared author APIs must support these real custom surfaces. Do not implement per-app copies of the algorithm. A reusable paint policy may live in the author/paint layer and be invoked by components after their content, because `ScrollRegion::draw` alone runs before content in some compositions. Preserve draw purity and theme paint provenance.

Proof CP-SCROLL-FADE: heights 3, 4, 11, 12; top/middle/bottom/fits; both built-in themes; RGB/ANSI256/ANSI16/mono; cursor/current/selected/hovered/reversed/marked cells; nonzero origin and clipping; resize across thresholds. Compare actual final cells and cursor, plus full application scroll scenarios. Existing oracle fade unit tests define expected arithmetic and exemptions.

### CP-02: Focus and editing must separate keyboard navigation from completed click

Oracle `53b8212f` changes `TextInput`, `TextArea`, and `CodeEditor` to one completed click entering edit at the pointer. It does not make ordinary keyboard focus start an edit. Main `input.rs:1181` and `textarea.rs:885` begin editing for every `Intent::FocusIn`. Main pointer handlers accept both `Press` and `Click`, while oracle Showcase handles field activation after release (`O:src/bin/showcase/app.rs:634`, `:655`). Main runtime and field handlers must jointly preserve the actual application event sequence. A library-only method test cannot establish Down/Up behavior.

`M:crates/tui/src/components/code.rs:1079` handles text pointers only when editable. Oracle `O:src/widgets/code.rs:535` moves the caret in read-only mode. Preserve that read-only interaction without enabling mutation. Test first click, second click, keyboard focus then Enter/typing, press-only then release outside, disabled input, read-only caret, secret display widths, CJK/emoji/combining graphemes, horizontal scroll, multiline positions, commit/cancel/blur and validation. Reconcile existing conformance expectations that currently encode auto-edit-on-focus; immutable UX has priority over older baseline behavior.

### CP-03: Grid/table activation is not merely double-click

Oracle `O:src/widgets/grid.rs:1322` computes whether the clicked cell is already current with no range selection; completed click on that cell begins editing or emits read-only activation. A different cell first moves the cursor. Main `M:crates/tui/src/components/grid.rs:2743` moves on `Press` and only edits/activates on `DoubleClick`. Implement oracle activation through generic keyed Grid behavior and application-selected row/cell navigation policy. Preserve current-row identity across sorting, edit validation preventing navigation, active-editor caret placement, reference-cell trailing action, row-number selection and fetch-more sentinel routing. Do not move database concepts into Grid.

Proof CP-GRID-EDIT pairs pre-click cursor/range state with Down/Up, typed edit intent, state/action, and frame. It includes initially current cell, previously different cell, range selection, locked cell, read-only table, inline/cycle/external/refused edit, and a reorder between publication and action. Existing keyed cursor/custom cell/blur/read-only/ragged tests must remain.

### CP-04: Read-only output text contracts need completion

Oracle `viewport.rs` has keyboard selection (`:1351`), logical retained reading position, producer caret identity, mark rendering, mutation-owned cache validity and source-preserving tab/control copy. Main `ViewportCmd` at `:242` contains only scroll/follow/copy commands; it lacks the oracle Shift navigation and Ctrl/Alt+Shift word/document selections. `ViewportState::retained` at `:792` deliberately does not move scroll offset, whereas the new oracle preserves the reading position while follow is off. Main exposes caller-managed `invalidate()` and `retained()`; downstream adapters must make mutation notification unavoidable without reintroducing an owned widget data model or trusting application callers to remember separate invalidation calls.

Main `viewport.rs:434` walks graphemes independently per style run. Oracle has `split_styles_never_split_a_grapheme_cluster`, so segmentation must occur across the logical line before applying style ranges. Preserve visible tabs/control geometry and exact copied source, including clipping a tab or wide grapheme. Oracle mark APIs and source identity must map into a reusable borrowed projection contract; application find may compose existing input and viewport rather than inventing a separate text viewer. Tail-follow also needs a non-tailing prose policy: oracle `ScrollPanel.tail == false` never enters follow, even on End, whereas current TextViewport End always enables follow.

Proof CP-TEXT-OUTPUT must replay keyboard and mouse equivalent selections; Shift+arrows/Home/End and Ctrl/Alt+Shift variants; Esc clearing; append/replace-last/front eviction/wholesale replacement; active drag eviction; caret eviction; mark retention; same-length mutation; resize/wrap; paused reading; reaching tail through wheel/track/key/drag; non-tailing prose End; plain/rich split graphemes and control/tab copy. Measure cold/warm/append/reflow work independently and retain existing performance assertions.

### CP-05: Diff adaptation must preserve width fallback and text projection

Oracle adds `review_falls_back_when_narrow_and_restores_when_wide`, `review_budget_reserves_scrollbar_and_recovers_on_resize`, `review_emphasis_keeps_complete_graphemes_and_column_widths`, and `tab_indented_review_aligns_context_changes_and_copied_text`. Main's projection cache chooses Review directly by state (`M:crates/tui/src/components/diff.rs:205`) and its six unit tests do not cover those contracts. Restore automatic effective review/unified fallback without overwriting caller-requested mode, reserve actual scrollbar geometry, and inherit fixed viewport text/selection/fade semantics. Keep borrowed `DiffSource`, revision/mode/width invalidation, and update-owned cache rebuilding. Add no parallel owned diff domain model.

### CP-06: Row override propagation has a known unimplemented channel

`M:crates/tui/src/collection/rowui.rs:29` retains only `label_patch`; `RowUi::part` at `:314` calls `ui.style` without an instance part-patch set; `ColumnsUi` at `:666` similarly retains only `label_patch`. The accepted architecture audit identifies row/cell override completeness as an obligation. The disposition ledger at `M:docs/audit/consolidation/disposition-ledger.md:468` rejected an unlanded test file because its tenth assertion required a library change that neither source worktree implemented. That disposition is evidence of missing implementation, not acceptance of a missing override channel.

Provide a borrowed row-author override channel that reaches custom parts and explicit columns, preserving documented precedence and allocation bounds. Preserve the existing distinction between component-owned parts and row-author-owned parts: component patches must not broadcast into unrelated row meta/cell/custom parts. Tests such as Tree's `owner_patches_reach_tree_parts_without_leaking_into_row_owned_parts` remain valid. Proof must use distinctive actual-cell sentinels for inherited defaults, explicit row-part overrides, explicit cell overrides, Clear/Inherit, siblings and clipped cells, exercising `RowUi::part`, `ColumnsUi` and `CellUi`. Named styled-part recording alone cannot prove paint consumption.

### CP-07: Shared props and disabled pointer boundaries need broad proof

Accepted architecture §73 requires a shared props construction path, retained disabled registrations that absorb pointer input, and centrally safe inert APIs. The architecture auditor reran the current configured props check: 208 configurations in 173 files passed. Its scan is limited to configured constant IDs and intra-module construction; it cannot prove every dynamic app surface uses one model for input and drawing. Existing `pointer_capture_eligibility.rs` covers targets changing eligibility after publication. Add production scenarios where a control becomes disabled while pressed/captured, a disabled control overlaps another owner, and modal/resize publication changes eligibility. Verify no activation leaks to a lower owner, no stale capture survives, no semantic selection is fabricated, and disabled frame styling remains exact. This is proof debt; the existing source/test evidence does not justify claiming all disabled controls are broken.

Root task graph may split large streams further; every split must retain the exact obligations above.

## Shared acceptance matrix for every family

Each matrix row inherits CP-COMMON: exact oracle geometry and cells at 120×40 and 40×10 component allocations plus actual app supported/narrow sizes; zero/one-cell/nonzero-origin clipping; Junie and Paper; truecolor/ANSI256/ANSI16/mono; each meaningful base/focus/hover/pressed/current/selected/disabled/read-only/active/inactive/busy/loading/error/empty state. Unsupported combinations are documented, not silently simulated as semantic states. Apply global family, variant, state, subtree, instance and exact-part sentinel overrides and replacement slots, then inspect painted cells and unaffected neighbors. Verify stable identity on reorder/insert/remove, borrowed non-static renderers, visible-only callback execution, draw-state invariance, real runtime actions and no registration for inert reference rendering. Static families still need visual/style/clip proof even when they have no input state.

Keep style resolution and replacement-slot painting distinct. ADJ-04 retains the accepted TextArea covered FIELD exception: its actual component-owned selected resolution changes while sibling/theme remain unchanged, even when later composition covers the affected paint. This exact source-backed style exception does not exempt documented SlotFn replacements from changing intended painted cells, permit measurement-only fake queries, or waive complete oracle frame equality.

The current `render_components.rs` states 40 components × eight states × two themes × truecolor/mono × two sizes = 2,560 digest lines. That is useful current regression coverage, but it lacks ANSI256/ANSI16 and the new oracle's interaction/fade/retention states. `conformance.rs` is capability-based and a case can omit behaviors by omitting a capability. Enumerate actual family/capability membership and supplement explicit oracle scenarios. Main baselines are never proof of equality to `02f5294b`.

Final completion requires every matrix family to have canonical owning task IDs, scenario IDs and executed evidence. The production implementations used by all four apps and the component tests must be the same reusable public APIs. No old `src/widgets` compatibility library, candidate-baseline regeneration, test-only alternate painter, copied per-app fade/editor/list implementation, or family part that resolves style without painting it can satisfy this ledger.

An application with separate paint and interaction models has not adopted the reusable architecture merely because both halves compile. The same borrowed props, values, identities and geometry must govern production drawing and production input. App auditors report this risk in Showcase fields/settings/grid, Jackin historical paint composition and TablePro painted placeholders. Their migration tasks must remove the enabling duplicate ownership; shared component gaps discovered during adoption must return to the owning component stream. Acceptance must mutate a real domain value, navigate/edit it through runtime input, and compare the next production frame against the oracle. A painted replica paired with a different hidden editable model fails this test.
