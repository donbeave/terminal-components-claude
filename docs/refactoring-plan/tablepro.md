## Domain ownership and dependencies

Retain TablePro ownership of connection/catalog records, SQL parser/classifier/executor, history, completion candidates, tab/result identity, pending SQL, safety policy and per-tab result models. Main already separates `domain.rs`, `grid_model.rs`, `filter_editor.rs`, `quick_switcher.rs`, `tabs.rs` and `workbench.rs`. Preserve their stable identity contracts. Shared components must remain domain agnostic: no SQL, table names, credentials, connection environments, filesystem persistence, or history policy in junie-tui.

Reusable prerequisites, in dependency order:

1. Runtime deterministic event/tick delivery, terminal resize, paste, cursor, color capability and alternate-screen teardown.
2. Public identity/action/update/read-only-draw contracts; focus ordering including zero-area stops; hit, hover, down/drag/up ownership; modal capture/dismissal and restoring prior focus.
3. Exact theme, typography/cell-width, one-row segments, panel borders/gutters, footer hints, wrapping/clipping, scrolling/fades, scrollbar and nested clipping.
4. Buttons, text inputs, choice/radio/select, tabs, forms, tree/list, code pane, chips and responsive split.
5. Grid with stable row identity and app-owned mutation model; generic cell edit/validation; selection/navigation/fetch-more/pending actions; Editor with generic completion/diagnostics/statement anchors.
6. Composed dialog facts/SQL/token body, Picker and completion popover; app composition uses only public APIs.
7. Connections, explorer/tabs, table/filter/structure, query/result/history/safety surfaces; application parity and lifecycle gate.

Do not copy legacy RenderCtx or direct focus/hit registries into app adapters. Do not “fix” parity by moving app-specific SQL or safety decisions into widgets. Reusable behavior needs shared tests; TablePro scenarios prove correct integration.

## Deterministic fixture and action contract

Each TSV row starts a fresh process unless explicitly sequenced within its row. The fixture is the oracle's `db::connections()`, `Catalog::acme_prod()`, seeded `History` and deterministic generated rows. The database is an in-memory demo, with no network drivers; Production is a fixture name. Connect/delete/save/copy/keychain copy are simulated UI operations. Do not add live DB, SSH, keychain, clipboard or persistent file access to reproduce them. A Q(sql) appearing within an action sequence means only Ctrl+T, i, literal SQL, Esc on the existing connection; it must not reset the selected safety mode. A fixture column containing multiple presets expands into a separate fresh scenario per preset.

Preset `C` starts Connections with no arguments. `W` starts `--connect Production`. `L` starts `--connect "Local PostgreSQL"`. `T` is W followed by Ctrl+O, literal `orders`, Enter. `Q(sql)` is W, Ctrl+T, i, literal SQL, Esc. `QL(sql)` is the same from L. Presets are event sequences, not private state injection. For generic reusable component-only fixtures use a distinct manifest kind and never claim app reachability.

Each `cp(name)` captures full terminal cells (glyph, fg/bg, modifiers), ANSI, text, cursor position/visibility, screenshot and logical focus/selection/scroll/overlay state from the harness. Exact expected cells come from the immutable oracle, never hand-authored “looks right” expectations. Capture all named checkpoints, not only final frames.

`focus(label)` means replay Tab/BackTab from the current state until the unique semantic control label is focused, with a finite upper bound equal to one measured oracle focus cycle; record exact key count in the expanded manifest. `click(label)` and `hover(label)` resolve a unique oracle visible label plus owning panel/control and store zero-based cell coordinates per geometry in that manifest. Candidate replay uses those same coordinates and key counts; it must not search its own changed layout. Ambiguous labels fail fixture compilation. Expansion is deterministic baseline-stage extraction: enumerate the oracle rendered FocusRing/HitRegistry in render order, match exact control ID plus label, choose the first interior non-border hit cell nearest rectangle center (tie top then left), and store both ID and coordinate. Labels in TSV may use documented aliases: SSL = Use SSL / TLS; SSH = SSH tunnel; Startup = Startup commands; Local only = Local only (no iCloud sync); Save & Connect = Save & connect; Prompt for password = Prompt for password on connect; BASIC/ADVANCED tabs = connection form tabs. No candidate-driven rediscovery or human choice is allowed. `activate(schema X)` means focus explorer, Home, traverse Down through its flattened rows to exact schema X, Enter; `select first connection` means Home then first non-group row. `repeat until zero` is bounded by the initial tab count and never an unbounded retry. Grid `cell(row,column)` is the select-only keyboard sequence defined below; `click-cell(row,column)` is the separately explicit current-geometry mouse action. Neither macro may hide the other's state-changing inputs. Mouse click is move/down/checkpoint/up, so pressed frames are included. Screen-space PTY mouse bytes use one-based coordinates after conversion.

`select(label,value)` means focus control, Enter, Home, Down repeated to exact value's oracle index, Enter. `replace(value)` on TextInput means Enter if not already editing, Ctrl+L, bracketed paste(value), Enter. On CodeEditor it means i if not already editing, Ctrl+L, bracketed paste(value), Esc. On grid inline draft it means Enter if not already editing, Ctrl+L, bracketed paste(value), Enter. Selection is Ctrl+L, not Ctrl+A (O:src/widgets/field_common.rs:104); Enter commits single-line inputs, while Esc commits CodeEditor (O:src/widgets/code.rs:336). Existing `i;replace` therefore never inserts a second i. `ticks(n)` is exactly n simulation Tick events in the deterministic harness. A query's first statement completes on tick 7; subsequent statements need 5 each. Connections finish on tick 12, connection tests tick 10, explorer lazy loads after three ticks. Runtime PTY capture uses text/state predicates with finite timeout and records the tick/animation phase; a wall-clock sleep is not an expected-state assertion.

Time has observable behavior: pressed flash expires at 140ms; temporary status after five seconds; runtime ticks animate at 80ms versus 400ms idle (O:app.rs:192,317). The implementation verification must support a controlled test clock; compare 0/139/140ms flash and 4999/5001ms status without masking legitimate text. Oracle pure harness currently uses Instant for these two values, so exact runtime phase capture is an explicit fixture-engineering requirement. Do not change oracle source or silently drop dynamic cells.

Save confirmation starts a distinct five-tick row-commit job (O:app.rs:1828–1834,339–344). TP-034 must capture Saving with pending edits, four ticks still pending, fifth tick saved/RowEdits recorded, and only then navigate History. Query's seven-tick duration is not the commit duration. TP-018's first Right moves from already-expanded public to Tables; retain that checkpoint, then End selects lazy audit and Right starts the actual three-tick load.

`cell(row,column)` means keyboard selection/reveal only, never a hidden mouse click or edit activation. Resolve the exact column's zero-based source ordinal and the one-based display row in the oracle active Grid, focus that real Grid through its normal focus cycle, send Ctrl+Home, Down exactly row−1 times, then Right exactly column-ordinal times, drawing after each input. Require the actual oracle cursor to identify that row/column and record its actual geometry/scroll/selection; missing rows/columns or a draft still editing fail expansion. Subsequent Enter is an explicit action whose source type/read-only/viewer behavior must be captured. Freeze every key and checkpoint before candidate execution. No private cursor/scroll assignment or state-changing pointer event may be hidden inside this selector.

`click-cell(row,column)` is separately explicit: resolve the cell already rendered in the current oracle state, with no hidden keyboard selection/reveal, and freeze its topmost HitRegistry hit, cell ID, owning Grid::locate result, clip/column geometry and interior non-reference-arrow coordinate. Missing registered geometry or a different topmost hit fails fixture expansion; a source Grid::locate(None) is not treated as an activatable cell merely because area_of returned a rectangle. Execute the ordinary move/down/checkpoint/up sequence and record its actual source dispatch result. Cases requiring edit/activation must establish their source routing guard; source-inert partial-hit cases remain explicit nonactivation observations, never silently scrolled into a different branch. Candidate replay uses frozen input only, never its own layout search.

Oracle current-cell clicks activate: grid.rs:1334–1341 enters inline editing or emits viewer/activation according to type; adding Enter afterward can commit or close it. TP-031 therefore separately proves current/different/repeated currency clicks. The original orders.notes input is retained in TP-037 at every ALL size: its first-row long text follows grid.rs:570–578's viewer branch, not inline editing. At120×40 after eight Right inputs, notes has a registered17-cell partial rectangle at(95,9) but lies outside grid.rs:1225–1235's routable-column interval: its click is inert, Enter opens its viewer and paste leaves pending edits empty. Other sizes must freeze their actual guard result, not copy that geometry assumption. Inline literal/save/dirty fixtures instead use short currency text, as source pending_edits_preview_and_save does; Ctrl+L explicitly replaces its original value. This correction preserves the notes and mouse branches rather than deleting them or asserting an impossible inline state.

Oracle routing exception: a Picker over an editing Query does not intercept bracketed paste. Ctrl+O and Ctrl+G remain available during editing; Picker opening retains editor editing, and app.rs:236–254 falls through Workbench::on_paste to QueryTab::on_paste (workbench.rs:1194; tabs.rs:1543). TP-071 runs both real input paths and captures unchanged picker query plus changed underlying SQL, including the revealed editor after Escape. Preserve this visible behavior through the app's explicit source-qualified Paste branch invoking TASK-025's narrow configured CodeEditor paste helper, which shares its core operation with normal Intent::Paste. Default modal capture remains enforced; do not add layer passthrough, hidden runtime intents, fake focus or duplicate app insertion logic. Dialog and Filter paste behavior has separate source-qualified coverage, including any exact Filter upper-field exception; historical amendments need explicit oracle disposition before execution.

Filter source routing is deliberately asymmetric (app.rs:237–246): only an editing lower Value receives bracketed paste; an editing upper `and` field consumes paste without insertion. F08a is deferred, not authority to redesign the oracle. TP-040 records unchanged upper text/editing and lower text after paste, then types the upper digits through actual key events. Single-line Enter in this Filter invokes Apply immediately (app.rs:1700–1715), so the general `replace` macro can close the modal before the next selector. TP-039–042 use explicit Enter/Ctrl+L/paste-or-type/Tab to commit a field while retaining the Filter for the named button. TP-040 separately preserves the original lower `replace(10)` early-Apply branch, including its empty upper value. Do not change the generic TextInput Enter behavior to make a bad trace appear reachable.

Chip selectors follow source focus ownership, not the shape of painted text. TP-042 records that the group is the focus stop; lead and individual chips are pointer targets, and no separate clear-all control exists (widgets/chips.rs:76–145,245). `click(chips lead)` is an actual completed pointer gesture that toggles match_all and focuses the group. The initial group cursor selects the first chip; Enter opens its editor, Escape restores the group, Space toggles it, Delete removes it and uppercase X clears all. `focus(chips lead)`, `focus(first chip)` and `focus(clear all)` are rejected expansions, not fabricated no-op input events. Also, a registered group does not imply Tab can escape current Grid navigation to reach it; this row uses the source pointer handoff explicitly.

All `ALL` rows expand at 80x24,100x30,120x40,160x50. Every scenario expands truecolor, 256, 16, explicit mono and NO_COLOR runtime profiles; preserve exact oracle default theme. Main's paper theme gets separate architecture regression tests because oracle TablePro CLI exposes no theme switch. Boundary rows add 71x20,72x19,72x20,101x30,102x30 and resize-in-place. Unicode rows preserve source graphemes and no ambiguous raster “exactness” claims. PNG renderer/font/color profile must be pinned and recorded.

The TSV is a scenario specification, not a custom replacement for task-format. Execution tasks must turn its rows into validated tui-snap action manifests, freeze oracle hashes/provenance and replay on main. No baseline is accepted until all checkpoints are action-reachable, stable on repeated capture and fully compared. Expected no-op behavior is also captured.
