## Behavioral repairs required inside main architecture

- BF01 — crates/tui/src/text/buffer.rs:83 and :135. Constructors and set_text do not enforce the oracle's single-line filtering and CRLF/CR normalization. For example, constructing a single-line draft from a string containing a newline retains a forbidden newline, whereas insertion filters it. The enabling condition is separate normalization policies at each mutation entrance. Restore one entry-point invariant inside the new private buffer, preserving sensitive storage replacement/redaction. TASK-013 and TASK-016 own behavior; oracle src/core/text.rs:15 defines normalization. Prove constructor, set_text, character insertion and paste against the same immutable grammar, including CRLF and lone CR, through CHK-004/005 rather than accepting main's existing tests as the oracle.
- BF02 — crates/tui/src/text/buffer.rs:207. Selection snaps to a UTF-8 scalar boundary, not a grapheme boundary; edits also lack post-mutation cluster repair. An offset inside e plus combining acute can select half a cluster, and insertion of ZWJ between emoji leaves the cursor inside the joined cluster. Scalar-valid offsets are being mistaken for editable grapheme boundaries. Restore atomic replacement and floor/ceil grapheme invariants within TextEditorCore/TextBuffer. TASK-013 owns this; retain the shared core and sensitive non-cloning semantics. Direct proof must include split-cluster selections and mutations that merge previously separate clusters, not only already aligned ASCII selections.
- BF03 — crates/tui/src/text/buffer.rs:243 and text/measure.rs:39. Scalar word scans and underscore-as-word differ from oracle grapheme/alphanumeric word motion. Combining marks and snake_case produce different cursor/deletion endpoints. TASK-013 must preserve oracle grammar through the new shared editing core, not restore raw app key handlers. The repair is a shared grapheme-based word predicate and movement/deletion walk; keyboard_editor inventory disposition and direct Ctrl-word trajectories must retain the original endpoints.
- BF04 — crates/tui/src/text/buffer.rs:400, especially :420 and :422–435. Empty or fully filtered paste deletes a selection but reports false because only inserted length is counted; TextEditorCore::apply maps false to Ignored. A selected nonempty string plus Paste("") changes text while reporting no visible change. The enabling condition is mutation reporting derived from inserted bytes rather than the complete replacement transaction. TASK-013/016 need exact edit-outcome/state proof for sensitive and ordinary drafts, with TASK-016 W01608 distinguishing TextInput's idle empty-paste editing transition from TextArea/code idle no-op behavior. Do not repair all empty pastes by a blanket Changed response.
- BF05 — crates/tui/src/text/fuzzy.rs:7. Per-grapheme lowercase equality is not oracle whole-string lowercase/scalar matching. Greek final sigma (label ΟΣ, needle ος) and a needle selecting a combining scalar differ; subsequence penalty also uses grapheme ordinal instead of oracle byte offset. Preserve the new grapheme-ordinal return API while implementing oracle match/ranking semantics and converting original offsets explicitly. TASK-013 owns matching, with consuming picker/app proofs. The original fuzzy_boundary inventory must cover matches, score ordering and highlighted original graphemes; changing the return-coordinate architecture back to byte indices is not the repair.
- BF06 — crates/tui/src/text/measure.rs:174. Hard wrapping emits an over-wide grapheme and may emit a preceding empty row. Oracle wrap("日",1) yields one ellipsis row; main's walk yields empty then over-wide text. The shared walk permits emission before establishing whether one glyph fits an empty row. Preserve shared wrap/wrapped_rows traversal but project over-wide graphemes to the oracle ellipsis before row accounting. TASK-013 owns exact rows and TASK-012 owns consuming geometry. Prove equality between row count and emitted rows at widths 0, 1 and wide-grapheme boundaries, not only ASCII words.
- BF07 — crates/tui/src/runtime/session.rs:55–67 and :127–130. The installed panic restoration calls restore_modes, which does not issue Show; the previous panic hook runs before TerminalSession Drop can call terminal.show_cursor. Oracle src/runtime.rs restores cursor visibility before the previous hook. A panic while the cursor is hidden therefore exposes an incompletely restored terminal to that hook. Add cursor visibility to the all-attempted restoration operation, retaining the existing partial-entry rollback and raw-mode restoration even after a failed output command. TASK-009 W00902 already requires actual Show plus termios observations before the prior hook; an ordering log or eventual Drop cleanup is insufficient. TASK-009/068 also must finish oracle suspend/resume and interrupted-poll handling under the accepted private backend exception, without reintroducing global UI state.
- BF08 — crates/tui/src/layout.rs:494–496; the test at :838 explicitly freezes the mismatch. Main keeps the first pane when minima fail on either axis. Oracle src/ui/layout.rs:116 keeps the first vertical pane, but :137 keeps the second horizontal pane. At width 80 with two 50-cell horizontal minima, main displays the wrong pane. - BF09 — crates/tui/src/ui/paint.rs:152–164 and :76–105. Each span is independently segmented, so spans containing "e" then a combining acute lose the mark; split ZWJ and regional-indicator sequences also stop being the original logical grapheme.
