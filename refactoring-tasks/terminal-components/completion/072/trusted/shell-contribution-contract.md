# Shell contribution and whole-scenario closure contract

TASK-032 and TASK-040 repair shell ownership before their applications' page slices. Full-frame shell navigation scenarios cross those later pages, so declaring those whole scenarios green at the shell stage would either force an unbounded page rewrite or conceal real mismatches. Neither is permitted.

## Separate proof products

[shell-contributions.tsv](shell-contributions.tsv) freezes ten source-qualified shell observation/assertion contracts. The independently qualified architecture operation checks these contracts under R-001 / AC-001 / CHK-006, alongside each task's R-002 / AC-002 architecture invariants. The full-frame comparator never treats these semantic observations as terminal-cell equality.

[shell-frame-contributions.tsv](shell-frame-contributions.tsv) freezes two nonempty selections of **complete** undersized-terminal checkpoints. Every selected frame is compared in full, including blank cells, styled wide continuations, modifiers, dimensions and cursor. R-001 / AC-008 / CHK-004 owns these selections. TASK-040 also owns the complete HO-CLI-PREVIEW stdout/stderr/exit contract under that same mapping. Selecting whole source-defined checkpoints is not permission to crop, mask, normalize, substitute or omit any cell within them.

Both tables are planning inputs to TASK-002/TASK-003 baseline expansion, TASK-070 runner qualification, TASK-071 accounting and TASK-072 architecture qualification. Copy them into the immutable catalog and baseline input bundle before dispatch. The baseline owners materialize all literal checkpoint identities, lane applicability, sizes, palettes and numeric actions from these exact source-only rules. The host rejects empty, extra, missing, duplicated or executor-selected contribution membership. Unknown future payload hashes are accepted only through the named producer's independently accepted receipt.

## Observation records

Each materialized shell observation is a distinct versioned record with contribution ID, parent scenario ID, immutable checkpoint ID, source/adapter provenance and exactly the state keys listed in the table. Adapters observe actual production handler/render state; they cannot replay a surrogate model or calculate the candidate verdict. Semantic identity mappings are frozen from the oracle before candidate execution. Geometry tuples retain exact terminal coordinates; counts, epochs, clock units, booleans and ordered stack/row identities retain their original meaning. Reject absent fields, unknown fields, wrong types, reordered ordered collections, missing original shell assertions or unqualified source seams. The architecture qualifier independently verifies extraction and assertions with wrong-route, wrong-focus, stale-geometry, reordered-handler, leaked-paste, early-expiry and missing-checkpoint counterexamples.

The tables name source symbols as well as line locations. Resolve each against oracle commit `02f5294bfdbf38004cc49130d0aff1d01f31434c`; a nearby stale line number cannot redirect the symbol. The baseline receipt records exact source spans, extraction schema and materialized observations. Candidate adapters cannot choose field names, assertion subsets or mappings.

## Parent frames remain required

Every parent transcript still captures complete direct/PTY artifacts and reports actual full-frame comparison results. Non-owned mismatches remain failed diagnostics in the immutable future-owner stage map; they are never reported as parity passes. Full-parent comparison is not a required green subset in the early shell check. TASK-039/TASK-050 own complete parent-scenario closure after all relevant page repairs. Their gates rerun all shell and whole-frame contributions and require the entire application's unresolved set to be empty.

Contribution acceptance changes only that contribution's closed identity. It cannot close its parent scenario, reduce the required frame set or authorize a baseline update. Previously closed contributions cannot regress. A full scenario closes only when every required complete checkpoint and every associated contribution passes on the exact same frozen tree. TASK-069 repeats the complete campaign union after integration.

## Traceability roles

- `primary` identifies the task that must prove the complete source obligation. Each APP scenario has exactly one primary owner.
- `baseline` identifies the immutable oracle capture producer; it does not prove candidate behavior.
- `contribution` identifies a separate source-qualified shell invariant checked by the architecture operation. It supplements, never replaces, the primary edge.
- `frame-contribution` identifies a nonempty source-defined set of whole checkpoints checked by the exact comparator. It does not establish its parent scenario's closure.
- `preservation` requires the app-closure task to rerun an obligation already primarily owned by an earlier repair slice.
- `integration` requires complete proof on the final integrated tree.

These roles are supplemental traceability data, not additional task-format schema fields. Canonical requirements, acceptance/check links and dependency metadata remain unchanged except for the explicitly declared additional AC-008 blocks.
